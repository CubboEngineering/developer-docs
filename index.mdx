The Cubbo Clients API lets you connect your own systems to Cubbo's fulfillment operation. You push orders,
keep your catalog and stock in sync, announce inbound shipments (replenishments), manage returns and receive
webhooks when something changes in the warehouse or during delivery.

The API is a JSON REST API with two environments:

| Environment | Base URL |
|---|---|
| Production | `https://api.cubbo.com/v1` |
| Staging | `https://api-staging.cubbo.com/v1` |

Staging has its own credentials and stores. Ask your Cubbo contact for a staging account to test
your integration before going live.

Every request except token creation carries a `Bearer` token. See [Authentication](/guides/authentication).

## Before you start

<Steps>
  <Step title="Get API credentials">
    Cubbo issues a `client_id` and `client_secret` per API account. Ask your Cubbo contact if you do not have them.
  </Step>
  <Step title="Exchange them for a token">
    Call `POST /v1/auth/token` and use the returned token as a `Bearer` token on every other request.
  </Step>
  <Step title="Know your store ID">
    Most endpoints take a `store_id`. One API account can have access to several stores; the API only
    answers for stores it is allowed to see.
  </Step>
</Steps>

## Conventions

- Request and response bodies are JSON (`Content-Type: application/json`).
- Dates and times are ISO 8601 strings in UTC unless the field says otherwise.
- Money fields are decimals in the store's currency.
- Identifiers (`id`, `store_id`, `order_id`) are integers. `order_number` is your own reference and is a string.
- Errors always come back as a JSON object with an `error` key. See [Errors](/guides/errors).
