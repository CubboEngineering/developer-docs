A Clients API da Cubbo permite que você conecte seus próprios sistemas à operação de fulfillment da Cubbo. Você envia pedidos,
mantém seu catálogo e estoque sincronizados, anuncia remessas de entrada, os recebimentos (replenishment), gerencia devoluções e recebe
webhooks quando algo muda no armazém ou durante a entrega.

A API é uma API REST JSON com dois ambientes:

| Ambiente | URL base |
|---|---|
| Produção | `https://api.cubbo.com/v1` |
| Staging | `https://api-staging.cubbo.com/v1` |

O ambiente de staging tem suas próprias credenciais e lojas. Peça ao seu contato na Cubbo uma conta de staging para testar
sua integração antes de entrar em produção.

Todas as requisições, exceto a criação do token, levam um token `Bearer`. Veja [Autenticação](/pt-BR/guides/authentication).

## Antes de começar

<Steps>
  <Step title="Obtenha as credenciais da API">
    A Cubbo emite um `client_id` e um `client_secret` por conta de API. Peça ao seu contato na Cubbo caso você não os tenha.
  </Step>
  <Step title="Troque-as por um token">
    Chame `POST /v1/auth/token` e use o token retornado como token `Bearer` em todas as outras requisições.
  </Step>
  <Step title="Saiba o ID da sua loja">
    A maioria dos endpoints recebe um `store_id`. Uma conta de API pode ter acesso a várias lojas; a API só
    responde pelas lojas que ela tem permissão para ver.
  </Step>
</Steps>

<Card title="Início rápido" icon="rocket" href="/pt-BR/quickstart">
  Crie seu primeiro pedido em cinco minutos.
</Card>

## Convenções

- Os corpos de requisição e resposta são JSON (`Content-Type: application/json`).
- Datas e horários são strings ISO 8601 em UTC, a menos que o campo indique o contrário.
- Campos monetários são decimais na moeda da loja.
- Identificadores (`id`, `store_id`, `order_id`) são inteiros. `order_number` é a sua própria referência e é uma string.
- Os erros sempre retornam como um objeto JSON com uma chave `error`. Veja [Erros](/pt-BR/guides/errors).
